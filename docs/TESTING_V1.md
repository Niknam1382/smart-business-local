# TESTING_V1 — چک‌لیستِ تستِ دستیِ نسخه‌ی ۱.۰.۰ · Manual test checklist for v1.0.0

> **قبل از عمومی‌کردنِ پروژه این فایل رو روی رباتِ واقعی (تلگرام *و* بله) بگذرون.** تست‌های خودکار (سرورهای جعلی) منطق رو
> تضمین می‌کنن؛ رفتارِ واقعیِ پیام‌رسان‌ها و درگاه‌ها فقط این‌جا معلوم می‌شه. هر خطا رو با «عددِ مرحله + اسکرین‌شات + فایلِ تشخیصی
> (تنظیمات ← امنیتِ داده ← فایل تشخیصی)» گزارش کن.
>
> *English: run this on real Telegram **and** Bale bots before going public. Use two accounts (owner + customer) and small amounts.*

## ۰) آماده‌سازی
- [ ] **پشتیبان بگیر** (تنظیمات ← امنیتِ داده ← پشتیبان‌گیری) — مخصوصاً اگه داده‌ی نسخه‌ی ۰.۵.۰ داری. برنامه خودش هم قبل از ارتقا پشتیبان می‌گیره (`backups/before-upgrade-*.zip`).
- [ ] دو ربات تست (یکی تلگرام، یکی بله) و دو حسابِ کاربری: «مالک» و «مشتری». مبلغ‌های تست کم باشه.
- [ ] برنامه رو اجرا کن؛ اگه دیتابیسِ قدیمی داشتی: بدونِ خطا باز می‌شه و محصولات/سفارش‌های قبلی هست. ✔ ارتقای دیتابیس.

## ۱) پیش‌نمایش داخلِ برنامه («تجربه‌ی ربات» ← پیش‌نمایشِ مشتری)
- [ ] «شروع» → منو ظاهر می‌شه؛ محصولات → کارت محصول → افزودن به سبد → نهایی‌کردن → فرم → کارت‌به‌کارت → دستورِ پرداخت.
- [ ] «پاک‌کردنِ پیش‌نمایش» سفارشِ باز رو لغو می‌کنه و سبد رو خالی می‌کنه.

## ۲) فروشگاهِ دکمه‌ای — **روی تلگرام، بعد دقیقاً همین‌ها روی بله**
- [ ] `/start` → منوی پایدار (محصولات / سبد / نهایی‌کردن / پیگیری) + خطِ «هوش مصنوعی».
- [ ] کاتالوگ با ۷+ محصول → صفحه‌بندی (قبلی/بعدی، شمارنده‌ی صفحه). با دسته‌ها: انتخابِ دسته → فقط محصولاتِ همون دسته.
- [ ] کارت محصول **با عکس**: عکس می‌آد؛ ➖/➕ فقط کیبورد رو عوض می‌کنه (پیام دوباره نمی‌آد)؛ «بازگشت» به لیست می‌ره.
      ⚠️ *بله:* ویرایشِ پیامِ عکس‌دار ممکنه ساپورت نشه — انتظار: پیامِ قبلی پاک و لیستِ تازه فرستاده می‌شه (بدونِ خطا).
- [ ] افزودن به سبد، دابل‌تپ (تعداد دو برابر نشه)، ➕/➖/🗑 در سبد، خالی‌کردن با تأیید، تعدادِ بیشتر از موجودی (محدود می‌شه).
- [ ] یک محصول رو از اپ غیرفعال کن / موجودی‌ش رو صفر کن، بعد روی دکمه‌ی قدیمیِ همون محصول بزن → پیامِ تمیز، نه خطا.
- [ ] چک‌اوت: هر فیلد (نام، موبایل با ارقامِ فارسی، آدرس، اختیاری‌ها با «رد کردن»، «قبلی»، «انصراف»). شماره‌ی اشتباه → دوباره می‌پرسه.
- [ ] وسطِ چک‌اوت دکمه‌ی «سبد» منو رو بزن → «ادامه / انصراف» می‌پرسه. برنامه رو ببند و باز کن → چک‌اوت ادامه دارد.
- [ ] کالای فیزیکی+دیجیتال: فرم اجتماعِ فیلدها؛ فقط دیجیتال: بدونِ آدرس.
- [ ] انتخابِ روشِ پرداخت → سفارش ساخته می‌شه؛ دابل‌تپ روی روش → فقط **یک** سفارش.
- [ ] «پیگیری سفارش» → وضعیت، زمانِ باقی‌مانده، لغوِ سفارش (با تأیید). سفارشِ منقضی: موجودی آزاد می‌شه.

## ۳) پرداخت‌ها (مبلغِ کم!)
- [ ] **کارت‌به‌کارت:** «✅ پرداخت کردم» → اعلان به مالک؛ شماره‌ی پیگیری رو بنویس → به مالک می‌رسه؛ `/confirm <id>` یا از صفحه‌ی سفارش‌ها → مشتری پیامِ تأیید می‌گیره و موجودی کم می‌شه.
- [ ] **بله‌پی:** مشتریِ بله فاکتورِ بومی می‌گیره؛ مشتریِ تلگرام لینکِ رباتِ بله → Start → فاکتور. پرداخت → تأییدِ خودکار (اگه فعاله).
- [ ] **زرین‌پال:** لینکِ پرداخت می‌آد؛ بعد از پرداخت ظرفِ چند دقیقه تأیید می‌شه.
- [ ] پرداختِ دیرهنگام (بعد از انقضای رزرو) → اعلانِ «paid_late» به مالک.

## ۴) محصولِ دیجیتال
- [ ] متن / لینک / فایل / کلید: بعد از تأیید، تحویل می‌رسه. تأییدِ دوباره (یا دکمه‌ی «ارسال دوباره») **کلیدِ تازه مصرف نمی‌کنه**.
- [ ] ربات رو موقتاً خاموش/قطع کن، سفارشِ دیجیتال رو تأیید کن → اعلانِ «تحویل نرسید»؛ ربات رو روشن کن → خودکار تحویل می‌ره.
- [ ] کلیدها تموم بشن → محصول «ناموجود» می‌شه، نه خطا.

## ۵) دکمه‌های سفارشی، FAQ، پشتیبانی
- [ ] دکمه‌ی لینک، پاسخ متنی، «تماس» (پیامِ شماره + کارتِ تماس؛ *روی بله اگه کارتِ تماس نیومد فقط متنِ شماره کافیه*)، «پرسش از AI».
- [ ] سؤالات متداول: فهرست و پاسخ.
- [ ] پشتیبانی: مالک با `/owner <کد>` ثبت شده باشه. مشتری «پشتیبانی» → مالک اعلان می‌گیره؛ پیام‌های مشتری به مالک می‌رسه و **AI جواب نمی‌ده**.
      مالک با *Reply* روی پیامِ فورواردشده جواب بده (⚠️ *بله:* اگه Reply کار نکرد، `/reply t<شناسه> متن` یا `/reply b<شناسه> متن` رو امتحان کن)، `/handoffs`، `/close`.
- [ ] «پایان گفتگو» از سمتِ مشتری. ساعتِ کاری: خارج از ساعت پیامِ مناسب می‌ره.

## ۶) حالت‌ها، زبان و متن‌ها
- [ ] حالتِ «مشاور»: هیچ کیبوردی نمی‌آد؛ دکمه‌های قدیمی بی‌اثرن. برگشت به «فروشگاهِ دکمه‌ای» بدونِ ری‌استارت.
- [ ] «سفارش با AI» (آزمایشی) مثلِ ۰.۵.۰ کار می‌کنه.
- [ ] زبان «انگلیسی» و «خودکار»؛ یک متن (مثلاً پیامِ تأیید) رو سفارشی کن؛ placeholderِ اشتباه رد می‌شه.

## ۷) محدودیت‌ها و حریم خصوصی
- [ ] سقفِ AI رو روی ۲ بذار → بعد از ۲ پیام «به سقف رسیدی»، دکمه‌ها همچنان کار می‌کنن؛ مالک اعلانِ ۸۰٪/۱۰۰٪ می‌گیره.
- [ ] کلیدِ قطعِ اضطراریِ AI: فوراً اثر می‌کنه؛ خاموشش کن → دوباره AI جواب می‌ده.
- [ ] `/forget` از مشتری: گفتگو، سبد و چک‌اوتِ نیمه‌کاره پاک؛ سفارشِ باز می‌مونه؛ مشخصاتِ شخصیِ سفارش‌های بسته‌شده پاک می‌شه.
- [ ] «ریستِ فقط داده‌های فروشگاه» (پشتیبانِ خودکار می‌گیره): محصولات/سفارش‌ها پاک، تنظیمات و توکن‌ها باقی.

## ۸) پروکسی (تلگرام)
- [ ] لینکِ اشتراکِ خودت (https) → «به‌روزرسانیِ همین الان» → تعدادِ پروکسی نمایش داده می‌شه. لینکِ خراب → خطای فارسی و لیستِ قبلی سالم می‌مونه.
- [ ] یک پروکسی رو قطع کن → جابه‌جاییِ خودکار؛ وقتی برگشت → بعد از چند دقیقه بازگشت به بهترین (رویدادها توی صفحه‌ی ربات‌ها).

## ۹) headless / Docker
- [ ] `python run.py --headless --data-dir <پوشه>` ربات‌ها رو بالا میاره؛ Ctrl+C تمیز می‌بنده؛ `python run.py --healthcheck` در حالِ اجرا ۰ برمی‌گردونه.
- [ ] `docker compose up -d` → `docker compose ps` وضعیتِ healthy؛ ری‌استارتِ container بدونِ از دست رفتنِ داده.

## ۱۰) پشتیبان و بازگردانی
- [ ] پشتیبان بگیر، داده رو عوض کن، بازگردانی کن → همه‌چیز برگشت. پشتیبانِ ۰.۵.۰ رو هم بازگردانی کن (خودکار ارتقا می‌یابد).

## موارد «تأییدنشده آفلاین» (اگه خراب بود گزارش بده؛ برنامه fallbackِ امن داره)
بله: شکلِ کیبوردِ پایدار (`keyboard`)، `answerCallbackQuery`، ویرایشِ پیامِ عکس‌دار، آپلودِ multipart برای عکس/فایل، `sendContact`، `reply_to_message`.
تلگرام: محدودیتِ ۶۴ بایتیِ callback (رعایت شده)، `request_contact`.
