# راهنمای تست فاز ۱

## ۱) تست سریع محلی (روی هر سیستمی، حتی بدون ویندوز)

```bash
pip install -r requirements-dev.txt
python run.py --web
```

مرورگر رو باز کن روی آدرسی که توی ترمینال چاپ می‌شه (چیزی شبیه
`http://127.0.0.1:xxxxx`). این دقیقاً همون اپه، فقط توی مرورگر به‌جای پنجره‌ی
دسکتاپ. اگه سیستم دسکتاپ داری (نه سرور)، `python run.py` (بدون `--web`) یه
پنجره‌ی واقعی باز می‌کنه.

### چک‌لیست چیزی که باید ببینی و امتحان کنی

- [ ] صفحه‌ی خوش‌آمدگویی با اسم برنامه و یه فیلد برای اسم
- [ ] بدون وارد کردن اسم، دکمه‌ی «بعدی» رو بزن — باید پیام خطا نشون بده
- [ ] اسمتو بنویس و برو جلو → صفحه‌ی انتخاب «فروشگاه» یا «مشاوره»
- [ ] یکی رو انتخاب کن (کارت باید حاشیه‌ی کهربایی‌رنگ بگیره) و برو جلو
- [ ] صفحه‌ی انتخاب هوش مصنوعی: «با API» رو بزن → باید فیلد آدرس API و کلید
      ظاهر بشه. «محلی» رو بزن → باید رم، تعداد هسته، مدل پردازنده، کارت
      گرافیک (یا «شناسایی نشد»)، و فضای آزاد دیسک رو نشون بده
- [ ] هر کدوم رو انتخاب کردی، برو جلو → باید برسی به صفحه‌ی «سیستم پرامپت»
- [ ] متن پیش‌فرض سیستم پرامپت باید متناسب با فروشگاه/مشاوره‌ای باشه که
      انتخاب کردی
- [ ] پایین صفحه فقط نمونه‌های همون دسته رو ببین (۴ تا) — اگه فروشگاه
      انتخاب کردی نباید نمونه‌ی مشاوره ببینی و برعکس. روی «استفاده از این
      نمونه» بزن → متن ویرایشگر باید عوض بشه
- [ ] «ذخیره کن» رو بزن → باید «ذخیره شد» نشون بده
- [ ] از نوار بالا برو به «تنظیمات» → باید انتخاب‌های قبلیت (نوع کسب‌وکار،
      نوع AI) رو نشون بده، با دکمه‌ی «تغییر بده» جلوی هرکدوم
- [ ] زبان رو به English عوض کن → کل رابط باید انگلیسی و چپ‌به‌راست بشه
- [ ] برنامه رو ببند و دوباره باز کن (`python run.py --web`) → باید مستقیم
      بره سراغ صفحه‌ی سیستم پرامپت، نه آنبوردینگ از اول (چون تنظیماتت ذخیره
      شده)

### چیزی که هنوز کار نمی‌کنه (طبیعیه، فاز ۲ و ۳ هستن)

کلید API که وارد می‌کنی واقعاً به هیچ مدلی وصل نمی‌شه، و حالت محلی هنوز مدلی
دانلود/اجرا نمی‌کنه — این دو دقیقاً موضوع فاز ۲ هستن. اتصال تلگرام/بله هم فاز
۳ هست.

## ۲) گرفتن exe واقعی ویندوز

این محیطی که پروژه توش ساخته شده لینوکسیه و نمی‌تونه مستقیم exe ویندوزی
بسازه؛ برای همین یه ورک‌فلوی گیت‌هاب اکشن گذاشتیم که خودش این کار رو روی یه
ماشین ویندوزیِ واقعیِ گیت‌هاب انجام می‌ده:

1. این پروژه رو به یه ریپازیتوری گیت‌هاب پوش کن (یا آپلودش کن).
2. برو به تب **Actions** توی ریپو — یه ورک‌فلو به اسم **Build Windows
   executable** باید خودش اجرا شده باشه (یا از همون تب، دستی اجراش کن:
   **Run workflow**).
3. بعد از تموم‌شدن (چند دقیقه طول می‌کشه)، روی اجرای همون ورک‌فلو کلیک کن و
   پایین صفحه یه فایل به اسم **SmartBusinessLocal-windows** برای دانلود
   هست — همون exe واقعیه.
4. اون exe رو روی یه ویندوز واقعی دانلود و اجرا کن و همون چک‌لیست بالا رو
   دوباره تست کن.

اگه توی مرحله‌ی ساخت (Actions) خطا خورد، لاگ کامل همون‌جا توی گیت‌هاب هست —
کپیش کن و بفرست تا دیباگش کنیم.

## ۳) چیزی که من قبلاً محلی تست کردم (برای شفافیت)

- منطق کامل آنبوردینگ (اسم → نوع کسب‌وکار → نوع AI → صفحه‌ی اصلی) رو با یه
  تست خودکار قدم‌به‌قدم شبیه‌سازی کردم — پاس شد.
- رفتار «کاربری که قبلاً تنظیماتشو ساخته» (باید مستقیم بره صفحه‌ی اصلی) و
  تغییر زبان رو هم همین‌طور تست کردم — پاس شد.
- رمزنگاری کلید API (که هیچ‌وقت به‌صورت متن‌ساده ذخیره نشه) رو تست کردم —
  پاس شد.
- خود فرآیند بسته‌بندی (`flet pack`) رو یه‌بار محلی (نسخه‌ی لینوکسی، فقط
  برای اطمینان از درست کار کردن مسیر) اجرا کردم و چک کردم فونت‌ها درست
  داخل فایل نهایی باندل شدن — پاس شد.

چیزی که من نمی‌تونم از اینجا تست کنم: ظاهر واقعی صفحات (چون محیط من صفحه‌ی
گرافیکی نداره) و اجرای واقعی exe روی ویندوز. برای همینه که چک‌لیست بالا رو
لازم داریم.
