# راهنمای تست فاز ۲

## ۱) تست سریع محلی

```bash
pip install -r requirements-dev.txt
python run.py --web
```

### حالت محلی (Local)

- [ ] توی صفحه‌ی «راه‌اندازی و آزمایش هوش مصنوعی»، رم، هسته‌های پردازنده،
      **مدل پردازنده**، **کارت گرافیک** (یا پیام «شناسایی نشد»)، و **فضای
      آزاد دیسک** رو ببین
- [ ] یه جمله درباره‌ی وضعیت GPU باید ببینی: اگه کارت گرافیک نداری یا AMD/Intel
      داری، باید صریح بگه که فعلاً از پردازنده استفاده می‌شه؛ اگه NVIDIA داری،
      باید بگه شتاب‌دهی گرافیکی در به‌روزرسانی بعدی میاد
- [ ] یکی از سه سایز مدل (کوچک/متوسط/بزرگ) رو انتخاب کن — پیشنهاد ما (⭐) باید
      بر اساس رمت باشه
- [ ] روی «تغییر مسیر» کلیک کن و یه پوشه‌ی دیگه (ترجیحاً روی یه درایو دیگه)
      انتخاب کن؛ فضای آزاد نمایش داده‌شده باید همون لحظه به‌روز بشه.
      **توجه:** این یکی رو باید روی نسخه‌ی دسکتاپ واقعی تست کنی، نه `--web` —
      انتخاب پوشه توی مرورگر پشتیبانی نمی‌شه
- [ ] «دانلود و آماده‌سازی» رو بزن — یه نوار پیشرفت باید ظاهر بشه و درصد
      بالا بره (بسته به سرعت اینترنتت، ممکنه چند دقیقه طول بکشه چون مدل‌ها
      حدود ۱ تا ۴.۵ گیگابایتن)
- [ ] وسط دانلود «لغو» رو بزن — باید متوقف بشه و فایل نصفه‌کاره پاک بشه
- [ ] دوباره دانلود کن و این‌بار بذار تموم بشه — باید علامت «آماده‌ست» ✓ ظاهر بشه
- [ ] پایین صفحه، توی جعبه‌ی «امتحانش کن»، یه سوال مثل مشتری بپرس (مثلاً
      «قیمت این محصول چقدره؟») — باید یه جواب واقعی از مدل محلی بگیری (ممکنه
      چند ثانیه طول بکشه)
- [ ] برنامه رو ببند و دوباره باز کن — باید بدون دانلود دوباره، بلافاصله
      «آماده‌ست» رو نشون بده (چون فایل مدل رو از دفعه‌ی قبل پیدا می‌کنه)

### حالت API

- [ ] اگه توی آنبوردینگ API رو انتخاب کردی، آدرس و کلید (مخفی‌شده، مثل
      `sk-a••••••1234`) رو ببین
- [ ] «تست اتصال» رو بزن — با یه کلید و آدرس واقعی باید «اتصال برقراره» ✓
      نشون بده؛ با کلید اشتباه باید پیام خطای واضح بده (نه کرش)
- [ ] توی جعبه‌ی «امتحانش کن» یه پیام بفرست و جواب واقعی از API بگیر
- [ ] همون سوال رو دوباره بفرست — باید فوری جواب بده (از کش)، نه با تاخیر
      دوباره از API

## ۲) گرفتن exe واقعی و تست کامل

همون روشی که فاز ۱ گفته شد (پوش به گیت‌هاب، دانلود از Actions). این بار حتماً
تست کن که:
- دانلود مدل محلی روی یه ویندوز واقعی (نه شبیه‌ساز) کامل می‌شه
- تغییر مسیر ذخیره با دیالوگ واقعی ویندوز باز می‌شه

اگه مرحله‌ی نصب llama-cpp-python توی Actions طول کشید یا خطا داد، برام بفرست
— این تنها بخشیه که نتونستم از محیط خودم مستقیم روی یه exe واقعی تست کنم؛
هرچند نسخه‌ی wheel آماده‌ی ویندوزش رو توی ایندکس رسمی پروژه پیدا و تایید کردم
که وجود داره (پس نصب باید سریع باشه، نه با کامپایل طولانی).

## ۴) اصلاحات پس از تست واقعی روی ویندوز (دور دوم)

با عکس‌هایی که فرستادی این‌ها پیدا و درست شدن:

- [ ] مشخصات سیستم الان باید کامل باشه: رم، هسته، **مدل پردازنده**، **کارت
      گرافیک**، فضای دیسک — همه با هم، بدون جا افتادن
- [ ] هر کارت مدل، اسم واقعی مدل (مثل Qwen2.5-1.5B-Instruct) و یه توضیح
      ساده‌ی «چرا این سایز» رو نشون می‌ده؛ کارت‌ها الان زیر هم (عمودی) هستن
- [ ] قبل از دانلود، حجم تقریبی نشون داده می‌شه؛ بعد از دانلود، حجم **واقعی**
      فایل جایگزینش می‌شه
- [ ] این بار دانلود رو با اینترنت واقعی امتحان کن — اگه فایل ناقص یا خراب
      دانلود بشه (قطعی اینترنت وسط راه و غیره)، برنامه دیگه نباید بگه
      «آماده‌ست»؛ باید خودش تشخیص بده و پیام خطا + گزینه‌ی تلاش دوباره بده
      (این دقیقاً همون چیزی بود که باعث می‌شد مدل محلی جواب نده)
- [ ] یه دکمه‌ی «حذف مدل» کنار «دانلود دوباره» اضافه شده — امتحانش کن
- [ ] توی حالت API، الان یه فیلد «نام مدل» می‌بینی (پیش‌فرض gpt-4o-mini) —
      دقیقاً همینو به سرویست می‌فرستیم؛ اگه سرویس دیگه‌ای/مدل دیگه‌ای
      می‌خوای، همین‌جا عوضش کن
- [ ] ظاهر کلی (سایه‌ی کارت‌ها، آیکون‌ها، نوار بالا با آیکون و پس‌زمینه‌ی
      فعال) عوض شده — نظر بده اگه هنوز جای کار داره

نکته: سایز مدل‌ها رو عمداً روی سه‌تا (کوچک/متوسط/بزرگ) نگه داشتم تا نگهداری
و تست ساده بمونه؛ اضافه‌کردن تنوع بیشتر (مثلاً خانواده‌های مدل دیگه) رو
می‌ذارم برای یه به‌روزرسانی بعدی، مگر اینکه الان براش وقت بذاریم.

## ۳) چیزی که من قبلاً محلی تست کردم

- منطق پیشنهاد سایز مدل (بر اساس رم) با چندین سناریوی رم مختلف
- دانلود واقعی یه فایل (از یه سرور آزمایشی محلی، چون این‌جا به هاگینگ‌فیس
  دسترسی مستقیم ندارم) شامل: پیشرفت درست، کنسل‌کردن، خطای ۴۰۴
- کل جریان از کلیک دکمه‌ی دانلود توی رابط کاربری واقعی تا نوشته‌شدن فایل روی
  دیسک، به‌صورت end-to-end
- ApiEngine با یه سرور آزمایشی سازگار با OpenAI: چت واقعی، کش سوال تکراری،
  خطای ۴۰۱، خطای اتصال
- LocalEngine: مسیرهای خطا (فایل نبود، کتابخونه نصب نبود) — نه اجرای واقعی
  مدل، چون کامپایل/نصب llama-cpp-python توی این سندباکس به‌خاطر پلتفرم
  غیرمعمولش کند بود؛ اما نصب رو با ایندکس wheel رسمی پروژه عوض کردم که این
  مشکل رو حل می‌کنه
- کل مسیر آنبوردینگ تا صفحه‌ی هوش مصنوعی و نویگیت بین هر سه تب
