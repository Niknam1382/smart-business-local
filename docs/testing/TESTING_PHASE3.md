# راهنمای تست فاز ۳

## ۱) چیزی که من (کلود) از قبل با تست خودکار پوشش دادم

قبل از هر چیز مهمه بدونی این تست‌ها دقیقاً چی رو پوشش می‌دن و چی رو **نه** —
چون تلگرام (`api.telegram.org`) و بله (`tapi.bale.ai`) از محیط توسعه‌ی من
اصلاً در دسترس نیستن (محدودیت شبکه‌ی sandbox)، **من نمی‌تونم واقعاً به
تلگرام/بله وصل بشم**. برای همین یه سرور جعلی Bot API نوشتم (دقیقاً هم‌شکل
تلگرام و بله) که روی `127.0.0.1` بالا میاد و کلاینت‌های واقعی (aiogram و
کلاینت بله‌ی خودمون) با HTTP واقعی بهش وصل می‌شن — یعنی کد واقعیِ ارتباط،
پارس‌کردن پاسخ، مدیریت خطا و قطع/وصل، همه با شبکه‌ی واقعی (فقط لوکال) تست
شدن؛ فقط خودِ سرور تلگرام/بله واقعی نیست.

با این روش، ۸۵ تست خودکار این‌ها رو پوشش می‌دن:

- ذخیره‌سازی مکالمه‌ها (SQLite): تاریخچه، حافظه‌ی هر مکالمه، بلاک‌لیست،
  همزمانی چند ترد، مرتب‌سازی درست لیست حتی وقتی چند پیام توی یه ثانیه برسن
- ادغام پیام‌های پشت‌سرهم: سکوت ۳ ثانیه‌ای، سقف ۱۰ ثانیه، استقلال مکالمه‌های
  مختلف، مقاومت در برابر خطا
- کلاینت بله: getMe، ارسال پیام (و تکه‌تکه‌کردن پیام بلند)، دریافت پیام و
  پیگیری offset، تبدیل خطاهای شبکه/فرمت به پیام فارسی، **بدون نشت توکن**
- پایپ‌لاین مرکزی: بلاک‌لیست، حافظه‌ی روشن/خاموش، محافظ سیل پیام (بیشتر از
  ۲۰ پیام در دقیقه از یه مکالمه نادیده گرفته می‌شه)، پردازش سریالیِ هر
  مکالمه (پیام دوم قبل از تموم‌شدن اولی صف می‌شه، نه هم‌زمان)، قفل موتور
  محلی (چون یه مدل محلی نمی‌تونه هم‌زمان چند مکالمه رو سرویس بده، ولی API
  می‌تونه)
- آداپتورهای تلگرام/بله (سرتاسری، با سرور جعلی): اتصال موفق، توکن نامعتبر،
  Conflict (نمونه‌ی دوم در حال اجرا)، وب‌هوک فعال، قطعی و بازیابی خودکار
  شبکه، توقف سریع (حتی وسط یه long-poll در انتظار)، ری‌استارت، پروکسی نامعتبر
- صفحه‌های «ربات‌ها» و «گفتگوها»: ساخته‌شدن بدون کرش (دقیقاً با تکنیک
  Page جعلی که MASTER_PROMPT برای Flet توصیه می‌کنه)، ذخیره‌ی توکن،
  دکمه‌ی تست اتصال، روشن/خاموش/ری‌استارت، هشدار «نیاز به ری‌استارت»،
  انتخاب مکالمه، سوییچ حافظه، بلاک/رفع‌بلاک
- کل مسیر برنامه: ورود به خانه بعد از آنبوردینگ، ناوبری بین تب‌ها، پاک‌سازی
  صحیح هنگام ترک یه صفحه‌ی «زنده» (بدون این، هر بار سر زدن به تب گفتگوها یه
  ترد پس‌زمینه‌ی جدید و بی‌پایان اضافه می‌شد)، روشن‌شدن خودکار ربات‌ها

برای اجرای خودت:

```bash
pip install -r requirements-dev.txt
pytest
```

## ۲) چیزی که فقط خودت می‌تونی تست کنی: اتصال واقعی

این بخش همون «تست پایان فاز» ئه که خودِ MASTER_PROMPT ازش خواسته: یه ربات
واقعی بساز، توکن بده، از یه اکانت دیگه چت کن.

### گرفتن توکن ربات تلگرام

۱. توی تلگرام با `@BotFather` چت کن.
۲. دستور `/newbot` رو بفرست و اسم + یوزرنیم دلخواه (باید به `bot` ختم بشه) رو بده.
۳. یه توکن شبیه `123456789:AAH...` بهت می‌ده — کپی‌ش کن.

### گرفتن توکن ربات بله

۱. توی بله با ربات رسمی `@botfather` چت کن.
۲. مراحل ساخت ربات رو طی کن (مشابه تلگرام).
۳. توکن رو کپی کن.

### آزمایش توی برنامه

```bash
python run.py --web
```
(یا مستقیم دسکتاپ: `python run.py`)

- [ ] توی تب **«ربات‌ها»**، توکن تلگرام رو بچسبون، «تست اتصال» رو بزن —
      باید `✓ اتصال برقراره — @یوزرنیم_رباتت` رو ببینی
- [ ] اگه تلگرام روی اینترنتت (بدون VPN) باز نمی‌شه — این برای خیلی از
      کاربرهای ایران معمول و مورد انتظاره — بخش «پروکسی تلگرام» رو باز کن و
      آدرس پروکسی/VPN محلی‌ت رو بده (مثلاً `socks5://127.0.0.1:10808`؛
      شکل دقیقش به نرم‌افزار پروکسی/VPN خودت بستگی داره) و دوباره تست کن.
      بله نیازی به پروکسی نداره.
- [ ] همین‌طور توکن بله رو بچسبون و تست کن
- [ ] «روشن کن» رو بزن — وضعیت باید به «متصل — @یوزرنیم» تغییر کنه
- [ ] از یه **اکانت دیگه** (گوشی دیگه یا اکانت تلگرام/بله دیگه) به ربات
      پیام بده، مثلاً «سلام» — باید طی چند ثانیه جواب واقعی از AI بگیری
- [ ] **تست دیباونس:** سریع پشت‌سرهم ۲-۳ پیام بفرست (مثلاً «سلام»، «قیمت
      گوشی X؟»، «کِی می‌رسه؟» با کمتر از ۳ ثانیه فاصله) — باید فقط **یه**
      جواب واحد بگیری که به همه‌شون با هم جواب داده، نه ۳ تا جواب جدا
- [ ] برو به تب **«گفتگوها»** — باید مکالمه‌ی همین مشتری رو با تاریخچه‌ی
      کامل پیام‌ها ببینی (تازه‌سازی خودکار هر ~۲ ثانیه)
- [ ] سوییچ «حافظه‌ی این گفتگو» رو خاموش کن، یه سوال بفرست که به پیام قبلی
      ارجاع بده (مثلاً «همون که گفتم چند تا می‌خوام») — چون حافظه خاموشه،
      ربات نباید زمینه‌ی قبلی رو یادش باشه
- [ ] روی «مسدود کردن مشتری» بزن، از همون اکانت دوباره پیام بده — نباید
      هیچ جوابی بگیره (نه خطا، فقط سکوت). «رفع مسدودی» رو بزن و دوباره
      پیام بده — باید جواب عادی برگرده
- [ ] یکی از توکن‌ها رو عوض کن درحالی‌که ربات‌ها روشنن — باید پیام «تنظیمات
      عوض شده؛ برای اعمالشون ری‌استارت کن» رو ببینی؛ دکمه رو بزن و تایید کن
      که با توکن جدید درست وصل می‌شه
- [ ] برنامه رو کامل ببند و دوباره باز کن — اگه «با باز شدن برنامه، ربات‌ها
      خودکار روشن بشن» فعال بود (پیش‌فرض همینه)، باید بدون کلیک اضافه، خودش
      وصل بشه
- [ ] (اختیاری، برای اطمینان از پیام Conflict) برنامه رو یه‌بار دیگه هم اجرا
      کن — نمونه‌ی دوم باید پیام واضح «هم‌زمان جای دیگه‌ای هم فعاله» رو نشون
      بده، نه کرش یا سکوت

### اگه مشکلی پیش اومد

فایل `bot.log` (توی پوشه‌ی داده‌ی برنامه — کنار `settings.json`) جزئیات فنی
هر خطا رو داره؛ توکن‌ها و آدرس پروکسی از توش پاک‌سازی شدن، پس اگه خواستی
برام بفرستیش مشکلی نیست.

## ۳) تصمیم‌های فنی این فاز (خلاصه — جزئیات کامل در MASTER_PROMPT.md)

- به‌جای `Dispatcher.start_polling` آماده‌ی aiogram، یه حلقه‌ی polling
  خودمون نوشتیم — چون نسخه‌ی آماده هر خطایی (توکن باطل، Conflict) رو می‌بلعه
  و برای همیشه دوباره تلاش می‌کنه؛ با حلقه‌ی خودمون، وضعیت نشون‌داده‌شده به
  کاربر همیشه راست می‌گه.
- به‌جای کتابخونه‌ی `python-bale-bot` (که GPL-2.0 هست)، یه کلاینت سبک خودمون
  برای بله نوشتیم — چون این پروژه قراره MIT باشه و GPL توی یه exe باندل‌شده
  می‌تونه مشکل لایسنس درست کنه.
- توکن‌ها و آدرس پروکسی مثل کلید API با Fernet رمزنگاری ذخیره می‌شن.
