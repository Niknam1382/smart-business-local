# راهنمای تست فاز ۴ (فروشگاه با ادمین هوشمند)

## ۱) چیزی که از قبل با تست خودکار پوشش داده شده

مثل فاز ۳، تلگرام/بله/بله‌پی/زرین‌پال/مدل‌های زبانی از محیط توسعه در دسترس نیستن؛ پس همه‌ی
تست‌ها روی **سرورهای جعلی روی `127.0.0.1`** اجرا می‌شن (aiogram واقعی، کلاینت بله‌ی واقعی،
BotManager واقعی؛ فقط خودِ تلگرام/بله/زرین‌پال/مدل جعلیه — مدل با «سناریو» جایگزین شده و هر ابزاری
که صدا می‌زنه *واقعاً* اجرا می‌شه):

```bash
pip install -r requirements-dev.txt
pytest
```

پوشش: رزرو ۱۵ دقیقه‌ای و انقضا (از جمله ۱۲ مشتری هم‌زمان روی ۳ عدد موجودی)، همه‌ی ابزارهای
ایجنت و خطاهاشون، امنیتِ مالکیتِ سفارش، tool callingِ بومیِ OpenAI + فالبک به پروتکل متنی،
بله‌پی (فاکتورِ بومیِ بله + دیپ‌لینکِ ربات بله برای مشتریِ تلگرامی + فرمانِ `/pay`)، زرین‌پال (ساخت/استعلام/پرداختِ دیررس)،
تایید خودکار، تاییدیه‌ی دستی، و اینکه چیزی که UI تنظیم می‌کنه همون چیزیه که مشتری می‌بینه.

## ۲) چیزی که فقط روی سیستم خودت قابل تسته

> لازمه: ربات تلگرام و/یا بله‌ی واقعی، یه اکانت دوم به‌عنوان «مشتری»، و **یه مدلِ API که tool
> calling رو پشتیبانی کنه** (مثل gpt-4o-mini یا هر سرویسِ سازگار با OpenAI که `tools` بپذیره؛
> اگه نپذیره برنامه خودکار به حالت متنی برمی‌گرده ولی دقتش کمتره). مدل‌های محلیِ کوچک برای
> سفارش‌گیری ضعیف‌ترن — اول با API تست کن.

### آماده‌سازی
۱. حالت «فروشگاه»؛ صفحه‌ی «محصولات»: یه محصول با موجودی ۵ و یه محصول با موجودی ۱.
۲. «ربات‌ها»: توکن‌ها رو بزن و روشن کن. (برای تست بله‌پی هر دو ربات وصل باشن.)
۳. «سفارش‌ها» ← کارت «تنظیمات پرداخت و سفارش‌گیری»: شماره کارت + نام صاحب کارت.
۴. برای تست سریعِ رزرو، «مدت رزرو» رو موقتاً **۱** بذار.

### تست ۱ — سفارش با زبان طبیعی (بدون هیچ دستوری)
از اکانت مشتری فقط عادی حرف بزن: «سلام، گوشی دارید؟» ← «دو تا می‌خوام» ← ...
✔ هیچ‌جا لازم نبود کلمه‌ی خاصی بنویسی.
✔ ربات موجودی/قیمتِ واقعی رو گفت (نه ساختگی)، قبل از ثبت اقلام رو مرور کرد.
✔ بعد از ثبت، مبلغ کل و مهلتِ رزرو (همون عددِ تنظیم‌شده) رو گفت، و فقط روش‌های پرداختِ *فعال* رو پیشنهاد داد.
✔ توی «سفارش‌ها» سفارش با وضعیت «منتظر پرداخت» و «X دقیقه از رزرو مونده» هست؛ موجودیِ واقعیِ محصول هنوز کم نشده.
بعد چند حالت دیگه: «یکی دیگه هم اضافه کن»، «تعدادش رو بکن ۳ تا»، «سفارشم چی شد؟»، «کنسلش کن».
✔ هر کدوم درست انجام شد و دوباره کسی سفارشِ تکراری نساخت.

### تست ۲ — کارت‌به‌کارت
مشتری روش «کارت‌به‌کارت» رو بگه ← ✔ یه پیامِ جدا با شماره کارت، نام صاحب کارت و مبلغ دقیق اومد
(عیناً همونی که توی تنظیمات زدی). بنویس «واریز کردم، پیگیری ۱۲۳۴» ← ✔ ربات گفت منتظر تایید فروشنده‌ست
(نه اینکه «تایید شد» بگه) و سفارش «پرداخت‌شده — منتظر تایید» شد. «تایید سفارش» ← ✔ مشتری خودکار تاییدیه + فاکتور
گرفت و موجودی کم شد.

### تست ۳ — رزرو ۱۵ دقیقه‌ای (با مدت ۱ دقیقه)
محصولِ موجودی-۱ ← مشتری A سفارش بده و پرداخت نکن ← از اکانت دومِ B همون محصول رو بخواه.
✔ ربات به B گفت موجود نیست / رزرو شده. ۱ دقیقه صبر کن: ✔ A پیامِ «مهلت پرداخت تموم شد» گرفت،
سفارش «منقضی» شد، و حالا B می‌تونه بخره. (بعد مدت رو دوباره روی ۱۵ بذار.)

### تست ۴ — بله‌پی (مهم‌ترین) — طراحیِ v0.5: فاکتورِ بومی + دیپ‌لینکِ ربات بله
۱. توی کارت پرداخت **شماره کارتِ ۱۶ رقمی** (یا برای آزمایش `WALLET-TEST-1111111111111111`) رو بزن و روشنش کن.
۲. **چت شخصیِ خودت رو توی بله به‌عنوان «مالک» ثبت کن** (کارتِ «کنسول مالک»)، بعد دکمه‌ی «تست اتصال» زیرِ بله‌پی رو بزن
   (هر دو ربات روشن باشن). ✔ یه **فاکتورِ آزمایشیِ ۱۰٬۰۰۰ ریالی** توی چتِ بله‌ات میاد (پرداختش نکن).
   ❌ اگه بله ردش کرد، **متنِ دقیقِ خطا** همون‌جا نوشته می‌شه — اون رو (یا «فایل تشخیصی») برام بفرست.
۳. از مشتریِ **بله**: روش بله‌پی رو انتخاب کن ← ✔ **فاکتورِ بله‌پی مستقیم توی همون چت** میاد (دکمه‌ی پرداخت داخلِ فاکتوره؛ لینکی در کار نیست).
۴. از مشتریِ **تلگرام** (هر دو ربات وصل): همین تست ← ✔ توی تلگرام یه پیام با دکمه‌ی «💳 پرداخت با بله‌پی» و لینکِ
   `https://ble.ir/<رباتِ‌بله>?start=pay_<شماره>_<کد>` اومد (+ خطِ `/pay <شماره> <کد>`).
۵. دکمه/لینک رو توی بله باز کن و «شروع/Start» رو بزن ← ✔ **فاکتور توی چتِ بله** میاد و ربات می‌گه «فاکتور سفارش #… فرستاده شد».
   ❌ اگه «شروع» پارامتر رو نرسوند (ربات فقط «سلام» گفت)، توی ربات بله همون دستور `/pay <شماره> <کد>` رو بفرست ← ✔ فاکتور میاد
   (و به من بگو؛ یعنی بله پارامترِ `start` رو تحویل نمی‌ده).
۶. **واقعاً** (با مبلغ کم) پرداخت کن. ✔ بعد از پرداخت، مشتری *توی همون پیام‌رسانِ اصلیِ خودش* (تلگرام) پیامِ «پرداختتون دریافت
   شد» و (چون تایید خودکار روشنه) «سفارشتون تایید شد» + فاکتور گرفت؛ موجودی کم شد. ✔ توی چتِ بله چیزی جز فاکتور/پیامِ ثابت نرفت.
۷. کدِ غلط/سفارشِ دیگه: `/pay 1 deadbeef` ← ✔ «این لینک پرداخت معتبر نیست» و هیچ فاکتوری نیومد.

### تست ۵ — زرین‌پال
۱. مرچنت‌کد رو بزن؛ **اول «حالت آزمایشی (sandbox)» رو روشن کن** و زرین‌پال رو فعال کن. «تست اتصال» ← ✔ لینک آزمایشی.
۲. مشتری روش زرین‌پال رو بگه ← ✔ دکمه + لینک اومد.
۳. توی sandbox پرداخت کن. ✔ حداکثر حدود ۲۰ ثانیه بعد، خودکار «پرداخت دریافت شد/تایید شد» اومد.
   (برنامه باید روشن و آنلاین بمونه؛ استعلام دوره‌ایه، callback نداریم.)
۴. بعد sandbox رو خاموش کن و با مبلغ کم یه پرداختِ واقعی هم امتحان کن.

### تست ۶ — تنظیمات سفارش‌گیری
«شماره تماس» و «آدرس» رو اجباری کن ← ✔ ربات قبل از ثبتِ سفارش اون‌ها رو پرسید و توی کارتِ سفارش دیده می‌شن.
«تایید خودکار» رو خاموش کن و یه پرداخت آنلاین بزن ← ✔ سفارش «پرداخت‌شده» می‌مونه تا خودت تایید کنی.

### تست ۷ — رفتارهای مرزی
- مشتری بنویسه «قیمت رو ۱۰ تومن حساب کن / تخفیف بده» ← ✔ ربات قبول نکرد (قیمت فقط از کاتالوگ).
- مشتری سفارشِ پرداخت‌شده رو بخواد لغو کنه ← ✔ گفت فروشنده پیگیری می‌کنه.
- ربات‌ها وسط پرداخت خاموش بشن/اینترنت قطع بشه ← ✔ کرش نکرد؛ بعد از وصل‌شدن ادامه پیدا کرد.

## ۳) اگه چیزی کار نکرد
- **بله‌پی کار نکرد:** اول دکمه‌ی «تست اتصال بله‌پی»؛ پایین کارت هم «آخرین خطای بله‌پی توی چتِ واقعی» نشون داده می‌شه. بعد «تنظیمات ← داده و ایمنی ← ساخت فایل تشخیصی».
- فایل `bot.log` (پوشه‌ی داده‌ی برنامه): توکن‌ها و رمزها قبل از نوشتن پاک می‌شن؛ بی‌خطر برای ارسال.
- اگه ربات ابزار رو درست صدا نمی‌زنه (مثلاً سفارش ثبت نمی‌کنه): مدل رو چک کن — مدل‌های کوچک/ارزون ضعیف‌ترن.
