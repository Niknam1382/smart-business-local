# راهنمای تست نسخه‌ی ۰.۵.۰ (قابل‌حمل، پشتیبان/ریست، پروکسیِ چندتایی، انتشار)

> چیزهایی که **فقط روی سیستم/فلش/GitHub خودت** قابل تستن. بقیه‌اش (۵۰۹ تستِ خودکار) روی سرورهای جعلی اجرا می‌شه:
> `pip install -r requirements-dev.txt && python -m pytest`. هر ❌ رو با «فایل تشخیصی» (تنظیمات ← داده و ایمنی) برام بفرست.

## ۱) بله‌پی
مثلِ «تست ۴» در [`TESTING_PHASE4.md`](TESTING_PHASE4.md) (فاکتورِ بومی + دیپ‌لینک). این مهم‌ترین تستِ این دوره‌ست.

## ۲) پشتیبان‌گیری / بازگردانی / ریست («تنظیمات ← داده و ایمنی»)
۱. چند محصول و یه سفارش داشته باش. «ساخت پشتیبان» ← ✔ مسیرِ فایل زیرِ دکمه نوشته می‌شه و داخلِ پوشه‌ی `backups` هست.
۲. یه محصول رو پاک کن، بعد از لیست «بازگردانی» رو بزن ← ✔ ربات‌ها خاموش شدن، محصول برگشت، پیامِ «نسخه‌ی قبلی اینجا موند: …before-restore-….zip».
۳. **ریست:** بخش «بازنشانی کارخانه» رو باز کن ← ✔ دکمه تا وقتی «ریست» رو تایپ نکردی خاکستریه ← بعد از ریست ✔ برنامه به صفحه‌ی معرفی برگشت، همه‌چیز خالیه
   و یه پشتیبانِ `…zip` توی `backups` هست. ✔ مدل‌های دانلودشده پاک نشدن (مگر تیکِ «مدل‌ها رو هم پاک کن»).
۴. «بازگردانی» با آخرین پشتیبان ← ✔ همه‌چیز (حتی توکن‌ها) برگشت. ۵. «ساخت فایل تشخیصی» ← ✔ زیپ ساخته شد؛ بازش کن و مطمئن شو توکن/شماره‌کارت/مکالمه توش نیست.
۶. **(ویندوز)** این تست‌ها رو یک بار هم وقتی ربات‌ها *روشن‌اند* انجام بده؛ ✔ خطای «فایل در حال استفاده است» نباید بیاد.

## ۳) نسخه‌ی قابل‌حمل (فلش)
۱. از Releases فایلِ `…-<سیستم‌عامل>-portable.zip` رو بگیر و روی فلش باز کن ← ✔ `portable.flag`، `SmartBusinessData/` و پوشه‌ی سیستم‌عامل هست.
۲. برنامه رو از داخلِ پوشه‌ی سیستم‌عامل اجرا کن، توکن/محصول وارد کن، ببندش ← ✔ فایل‌های `settings.json`، `*.db`، `secret.key` **روی فلش** (داخلِ `SmartBusinessData`) ساخته شدن، نه توی `%APPDATA%`.
   (توی «تنظیمات ← داده و ایمنی» مسیرِ داده و «حالت قابل‌حمل روشنه» رو ببین.)
۳. فلش رو به **یه کامپیوتر دیگه** (یا سیستم‌عاملِ دیگه، اگه zipش رو هم باز کردی) ببر ← ✔ با همون اطلاعات باز می‌شه و توکن‌ها هنوز کار می‌کنن.
۴. فلشِ قفل‌شده (write-protect) ← ✔ برنامه کرش نمی‌کنه و به پوشه‌ی معمولیِ سیستم برمی‌گرده.

## ۴) پروکسیِ تلگرام (فقط اگه تلگرام بدونِ پروکسی بازنمی‌شه)
۱. چند پروکسیِ SOCKS5/HTTP توی «ربات‌ها ← پروکسی‌ها» بذار (هر خط یکی)، یکی‌شون عمداً خراب ← ✔ زیرِ فیلد «N پروکسیِ معتبر — با قطعِ یکی، خودکار به بعدی می‌رم».
۲. «بررسی و رتبه‌بندی» ← ✔ سالم‌ها بالا با میلی‌ثانیه، خراب پایین (✗). ۳. «تست اتصال» توکن ← ✔ از طریقِ اولین پروکسیِ سالم وصل می‌شه.
۴. ربات تلگرام رو روشن کن، بعد پروکسیِ فعال رو قطع کن (یا یه پروکسیِ خراب رو اول بذار) ← ✔ بعد از چند ثانیه توی `bot.log` «پروکسی تلگرام عوض شد» می‌بینی و پیام‌ها دوباره جواب داده می‌شن؛ هیچ پیامی گم/تکراری نشد.
۵. خطِ `tg://proxy?…` بذار ← ✔ پیامِ فارسیِ «MTProto برای ربات‌ها کار نمی‌کنه».

## ۵) انتشار روی GitHub (`release.yml`)
۱. پوش ← **Actions ← CI** ← ✔ سبز (ویندوز/مک ممکنه قرمز/زرد باشه؛ آزمایشی‌اند). ۲. (اگه هست) `build-windows.yml` رو پاک کن.
۳. `git tag v0.5.0 && git push origin v0.5.0` ← **Release builds** ← ✔ ویندوز سبز؛ مک/لینوکس/نصب‌کننده آزمایشی. اگه قرمز شد لاگِ مرحله‌ی قرمز رو برام بفرست.
۴. Release باید این فایل‌ها رو داشته باشه: `…-windows-setup.exe`، `…-windows.exe`، `…-windows-portable.zip`، `…-macos-portable.zip`، `…-linux-portable.zip`، `SHA256SUMS.txt`.
۵. exe/نصب‌کننده رو روی یه ویندوزِ تمیز اجرا کن ← ✔ باز می‌شه (SmartScreen هشدار می‌ده؛ طبیعیه)، با «ربات‌ها ← تست اتصال» کار می‌کنه.
